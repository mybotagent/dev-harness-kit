정의

리서치 하네스는 플랜을 외부 자료로 검증한다. 단순 검색이 아니라 루브릭 우선으로 동작한다:

  1. "어떤 차원을 검증할 것인가" 정의 → 명시적 루브릭
  2. N개 (≥3) 독립 웹 쿼리 팬아웃
  3. 인용 + 교차검증 (N 소스 합의)
  4. 종합은 모델이 제안, verification 게이트가 검증

insane-search의 Phase 0–3 에스컬레이션을 차용하되, MCP 서버로 재구성 (Claude plugin 배포는 기각).

인증/페이월 만나면 즉시 중단 (insane-search의 경계 그대로).

단일 출처 경고가 미해결이면 리서치 결과 게시 거부. 단, 정보가 단일 출처에서만 가능한 경우는 (예: 미공개 내부 문서) 명시적 표시 후 통과.

인용 강제 (결정 5)

모든 주장에 인용 필수:

  • URL
  • 검색 시각 (ISO 8601)
  • 출처 종류 (1차 / 2차 / 비권위)
  • 접근 방법 (HTTP / 인증 / 내부)

인용 없는 주장 = 게시 거부. 단, 명시적 "주관적 판단" 마킹 의 경우는 인용 면제 (예: 모델의 디자인 결정).

N 소스 합의 패턴

  루브릭 정의 (검증 차원 N개)
      │
      ▼
  N=3개 쿼리 팬아웃 (`tools/parallel_dispatch.py`)
      │  각 쿼리는 다른 쿼리 + 다른 소스
      ▼
  N개 응답 수집 → URL 인용 추출
      │
      ▼
  비교: 동일 결론?
  ├── 모두 일치 → 신뢰 상향 + 종합 진행
  ├── 2-of-3 일치 → 부분 합의 + 명시
  └── 1-of-3 일치 → 신뢰 하향 + 경고 표시
      │
      ▼
  종합 (모델이 초안), 게이트가 검증
      │
      ▼
  결정: 게시 / 부분 게시 + 경고 / 거부

컴포넌트위험비고

웹 페치매우 낮음실제 I/O

인용 강제매우 낮음결정적
종합높음 — 흡수 가능얇게: 엔진은 출처만 수집; 종합은 모델이 초안, 게이트가 검증

결정적 강제: verification 게이트, 인용 강제, N 소스 합의. 모델이 흡수할 수 없다.

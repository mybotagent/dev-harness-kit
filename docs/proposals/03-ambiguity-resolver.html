정의

인터뷰 하네스는 구현 전에 에이전트가 사용자 / 이해관계자에게 구조화된 질문을 던져 플랜 모호함을 해소하는 루프다. 모호함이 있는 플랜은 구현해도 의도와 어긋날 확률이 높다 — 인터뷰는 그 어긋남을 사전에 잡는다.

모호함 점수(LLM judge 채점)가 임계값 이하로 떨어지거나 safety_valve 도달 시 종료.

모호함이 해소된 플랜은 lcs://interview/<session>에 영속화되어 다음 에이전트 / 다음 단계 (04-quality-judge의 평가 → 05-value-gate의 가치 판단)가 읽는다.

기존 plan 구현과의 정렬 (필수 일치)

인터뷰 하네스는 기존 /dev-kit:plan 스킬의 Gate 2/4 검증 루프(=skills/plan/SKILL.md §2.3) 와 동일한 JSON 형태 + 종료 임계값을 사용한다. 재발명 금지, 패턴 차용.

점수 계산 — LLM Judge (self-rescore)

모호함 점수는 LLM judge가 채점한다. 키워드 매칭 / 규칙 기반 점수 계산은 기각한다. 이유는 다음과 같다:

  • 모호함은 의미적 판단 (예: "트레이드오프가 충분히 명시화되었나?")

이라서 결정적 함수로 표현 불가

  • LLM judge는 reasoning + 점수를 함께 출력 → 근거 강제 가능
  • 다중 judge + 적대적 교차검증 (Evaluation과 동일 패턴)으로

judge 편향을 차단

점수 채점 인터페이스 (의사)

# lib/interview_engine.py
class AmbiguityJudge(Protocol):
    """LLM judge interface. Implementations are NOT deterministic."""
    def score(self,
             plan: Plan,
             history: list[QA],
             knobs_covered: set[str]) -> tuple[int, str]:
        """Returns (score 0-10, reasoning). Lower = less ambiguous."""

class AmbiguityRubric:
    """Concrete dimensions the judge scores on."""
    user: int         # 0-2 (0=clearly identified first user)
    pain: int         # 0-2 (0=clearly identified pain + frequency)
    scope: int        # 0-2 (0=smallest viable scope defined)
    metric: int       # 0-1 (0=success metric defined)
    kill: int         # 0-1 (0=kill criteria defined)
    contradiction: int  # 0-1 (0=no contradictions in history)
    unfilled: int     # 0-1 (0=no open questions remaining)

다중 judge + 적대적 검증

  1 judge → 1 score + reasoning
  → N=3 judges (적대적: 각 judge 다른 모델 또는 같은 모델 다른 seed)
  → 점수 평균 + 분산
  → 분산 > 임계값 → 추가 judge 소집 (variance gate)
  → 최종 점수

분산 게이트는 Evaluation(04-quality-judge.html)과 동일 패턴.

질문의 5가지 유형 + 1개 합성

5가지 표준 유형 + 사용자 의도 정량화 1개:

유형의도영향 knob
가정 확인숨은 가정 명시화user (-1), unfilled (-1)
트레이드오프의사결정 자료 명시화pain (-1), unfilled (-1)
스코프 경계범위 명시화scope (-1), unfilled (-1)
사용자 의도모호한 용어 정량화metric (-1)
위험 인정트레이드오프 명시적 인정kill (-1), contradiction (-1)
합성 검증"위 답변들 사이 모순이 있나?"contradiction (-1)

합성 검증은 1라운드 이후 매 답변 후 자동 실행. 모순 발견 시 다음 라운드 우선순위로.

메커니즘 — Ralph 스타일 루프

  초기:
    ambiguity_score = 10
    knobs_covered = {}
    history = []
    decision_log.md → append "# interview start"

  ROUND loop (safety_valve=8):
    1. judge.score(plan, history, knobs_covered) → (score, reasoning)
    2. decision_log.md ← append {round, score, reasoning, knobs_covered}
    3. loop_log.json ← append {round, score, knobs_covered}

    4. if score <= THRESHOLD (3): BREAK ("converged")
    5. if score same as previous (narrowed_delta == 0):
         consecutive_same += 1
         if consecutive_same >= 2: BREAK ("best effort")
    6. if score > previous: ERROR (LLM judge inconsistent)

    7. knob = pick_highest_leverage_knob(score_breakdown, knobs_covered)
    8. question = generate_question(plan, knob)  # model-driven
    9. answer = prompt_user(question)            # adapter
    10. history.append((question, answer))
    11. knobs_covered.add(knob)
    12. plan = apply_answer(plan, answer)

  POST:
    lcs://interview/<session> ← {score, reasoning, knobs_covered, history}
    decision_log.md ← append "# interview end: status=<converged|best-effort>"

종료 조건 — 결정적 임계값 + 안전장치

1차 종료: 점수 임계값 도달 (PASS)

PASS iff  ambiguity_score <= 3
          AND judge_variance < variance_threshold (0.5)
          AND knobs_covered >= {user, pain, scope, metric, kill}
          AND consecutive_contradictions == 0

→ status = converged. 플랜 가치 평가로 인계.

2차 종료: safety_valve (HELD)

if rounds >= 8 OR consecutive_same_score >= 2:
  BREAK with status = "best-effort"

→ status = best-effort. 모호함 점수 + 미해결 knob 명시. 플랜 가치 평가가 hold 결정 가능. 사용자에게 "best effort" 알림.

3차 종료: 사용자 명시 단축 (USER_DONE)

if user_signoff == "충분하다" OR "더 묻지 말라":
  BREAK with status = "user-acknowledged"

→ status = user-acknowledged. 점수 임계값 무시.

4차 종료: 사용자 거부 (REJECTED)

if user_signoff == "그만" OR 거부:
  BREAK with status = "rejected"

→ status = rejected. 플랜 가치 평가에 kill 위임.

우선순위

1차 (점수) > 3차 (사용자 승인) > 2차 (safety_valve) > 4차 (거부)

거부(4차)는 즉시 종료. 안전장치(2차)는 1차/3차 도달 못할 때만.

narrowed_delta 강제 (LLM judge 비결정성 보정)

LLM judge는 비결정적이므로 strictly decreasing score 강제:

for round in 1..safety_valve:
    new_score = judge.score(plan, history, knobs_covered)
    if new_score > prev_score:
        # judge가 모순됨. 추가 judge 소집.
        alt_score = alt_judge.score(plan, history, knobs_covered)
        if alt_score < prev_score:  # 적대 judge는 좁힘 확인
            new_score = max(new_score, alt_score)  # 보수적 채택
        else:
            # 둘 다 넓힘 → 진짜 모순. 사용자에게 에스컬레이션.
            emit_contradiction_to_user(prev_score, new_score, alt_score)
    if new_score == prev_score:
        consecutive_same += 1
        if consecutive_same >= 2: BREAK
    prev_score = new_score

dedup_metric: identical-ambiguity-cycle=2. plan skill의 패턴 그대로 차용 (skills/plan/SKILL.md §2.3).

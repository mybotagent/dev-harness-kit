# Session monitor

`tools/session_monitor.py` lists every Claude Code and Codex session
captured by `/dev-kit:log` across this repo's worktrees, with live / idle /
stale status. Pick one with the inline arrow-key UI and the tool emits the
exact `cd <wt> && claude --resume <sid>` resume command for you to run with
`!`. A stdlib-only inline picker is also available over `ssh` / from a
plain shell.

## Modes

| Mode | When to use |
|---|---|
| Interactive picker (default, TTY required) | Local terminal / `Terminal.app`. Arrow keys + Enter. |
| `--list` | Plain stdout listing — works without a TTY, safe to run from any harness. |
| `--json` | Machine-readable output for scripts / skill consumers. |
| `--print-resume-command` | Print the cwd + argv for the first session, then exit (no picker, no exec). Useful for scripting. |
| `--cli-setup` | Install a `session-monitor` shell alias into `~/.zshrc` / `~/.bashrc` (idempotent), then exit. |

## Quick start

```bash
# Interactive inline picker (real TTY required — arrow keys + Enter)
python3 tools/session_monitor.py

# Plain listing (works without a TTY; safe to run from any harness)
python3 tools/session_monitor.py --list --days 30

# Machine-readable JSON for scripting / non-Claude-Code callers
python3 tools/session_monitor.py --json --days 30 | jq '.total_sessions, .live_sessions'

# Debug the resume argv synthesis for the first session
python3 tools/session_monitor.py --print-resume-command
# -> cd /Users/sanghee/dev/dev-harness-kit && claude --resume <sid>

# Install a `session-monitor` shell alias into your rc (idempotent)
python3 tools/session_monitor.py --cli-setup
# -> then: source ~/.zshrc   (now `session-monitor` works from any cwd)
```

## Flags

| Flag | Default | Purpose |
|---|---|---|
| `--days N` | `30` | Look-back window; older sessions are dropped |
| `--repo <name>` | (none) | Substring filter on the repo basename |
| `--logs-dir <path>` | `<main-repo>/logs` | Root for `claude-code/` and `codex/` subdirs |
| `--list` | off | Plain stdout listing (previewable in any harness) |
| `--json` | off | Machine-readable output for scripts / skill consumers |
| `--print-resume-command` | off | Print the cwd + argv for the first session; exit |
| `--cli-setup` | off | Install a `session-monitor` alias into `~/.zshrc`/`~/.bashrc` (idempotent); exit |
| `--filter PATTERN` | (none) | Substring filter (case-insensitive) across session_id, branch, model, source, log_path, worktree, status |
| `--picker` | off | Require interactive picker; error out (instead of silently degrading to `--list`) when not on a TTY |
| `--skill-usage` | off | Attach per-worktree top-skills + a global top-10 panel using `tools/skill_usage.py` over the same logs |
| `--skill-days N` | `30` | Window (days) for `--skill-usage` aggregation (pass `0` to disable) |
| `--dry-run` | off | With `--cli-setup`, print the alias block without writing |

## Status semantics

| Glyph | Status | Meaning |
|:---:|---|---|
| `●` | `live` | A running `claude`/`codex` process is cwd'd into the session's worktree, OR the last turn landed within the 180 s recency window |
| `○` | `idle` | Captured and within `--days`, but not recently active |
| `⌀` | `stale` | Worktree is merged into `main` or gone; resume falls back to the main checkout |

## How the picker works

The interactive picker is built directly on `termios` + ANSI escapes
(stdlib only, no `curses`, no third-party deps). On `Enter` it restores
the original `termios` mode, `cd`s into the session's worktree, and
`exec`s `claude --resume <sid>` (Claude Code) or `codex resume <sid>`
(Codex) — `exec` replaces the Python process so the user lands directly
in the resumed session. If the worktree is gone or merged, the picker
falls back to the main checkout and prints a warning.

Each session's `branch` is overridden with the worktree's current
`git rev-parse --abbrev-ref HEAD` so the picker shows the branch the
worktree is *actually* on, not the one captured at save-log time. Stale
worktrees (merged/gone) and detached-HEAD worktrees keep the log-captured
branch as a fallback.

The picker UI is intentionally a single-pane inline pattern (arrow keys to
move, Enter to resume, `q` / `Esc` / `Ctrl-C` to cancel) — the same "pick
one of N" pattern Claude Code's own `AskUserQuestion` uses — so the
rendering stays inside the terminal's normal scrollback and the user never
loses their last command's output.

## Why a tool alongside a skill

The skill needs the harness (to render `AskUserQuestion`); the CLI needs a
TTY (to render the picker). They share one data layer —
`discover → aggregate → group → enrich → render` — and the skill's
`--json` mode is literally the CLI's JSON output piped into the model.
No LLM sits in the loop for either; both are pure consumers of the
`/dev-kit:log` transcripts.

This is the same shape as [`/dev-kit:token-analyzer`](token-efficiency.md):
the skill makes the data accessible inside a Claude conversation; the CLI
makes it accessible from a plain shell, over `ssh`, or in CI. The CLI
form stays alive because it is genuinely CLI-friendly (no TTY required
for `--list` / `--json`; the picker is opt-in).
